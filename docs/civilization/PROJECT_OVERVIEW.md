Актуализировано 3 ноября 2026 года: база `bca2bd7c1534f006f21188644c47ed2acbcb1aa2`, ветка `codex/civilization-upstream-sync`, плюс локальные задачи 2–8. Этот документ описывает существующий код и места последующей интеграции. Полная игра из ТЗ пока не реализована.

## Исполняемый проект

Текущий продукт — режим `--civilization` в собственном native-форке Horizon. Это Rust-реализация Minecraft Java Edition 26.3, протокол 777, Cargo workspace. Fabric, Forge, NeoForge и Java-мод не используются. В `horizon-client/Cargo.toml` указан Rust 1.90, в `horizon-mods/Cargo.toml` — 1.95, поэтому для этой сборки нужен Rust не ниже 1.95; edition 2024. Графика использует wgpu 30 и winit 0.30.

Корневые `src/`, `Cargo.toml`, `horizon-mod.toml` и `scripts/Build-Mod.ps1` в родительской папке относятся к архивному WASM-прототипу. Его экономика и окна не являются функциональностью текущего клиента. Корневой `Play-Civilization.cmd` запускает проверенный native-пакет от 2 ноября.

`horizon-client` содержит игровой runtime, встроенный и dedicated-сервер. `horizon-client-lib` содержит переиспользуемые системы и `horizon-ctl`, без gameplay. `horizon-mods` содержит чистые модели кампании и самостоятельных NPC. Native Hooks API 359 и Owned NPC API 1 — отдельные контракты; номер WASM API из `api_level.rs` не заменяет их.

## Поток операции

Клиент отправляет команду или взаимодействие. Сервер получает UUID действующего игрока, проверяет членство, позицию, данные мира и инвентарь, затем меняет модель. При ошибке записи операции основания и сдачи откатывают копии модели/инвентаря в памяти. Клиент получает подтверждение и отображение. NPC не используют ванильный Brain как модель гражданина.

Кампания хранится в `horizon-civilization.json` в каталоге мира. Текущая схема — 3, форматы 1/2 мигрируют с точными копиями `.json.v1.bak` / `.json.v2.bak`. Максимум 4 МиБ; неизвестные поля и некорректные данные отклоняются. Запись идёт через уникальный соседний временный файл, sync и rename. Повреждённый файл не заменяется пустой кампанией. Это не общая аварийная транзакция с Minecraft playerdata.

## Сборка и проверка

Из `horizon-fork` с настроенным локальным Rust toolchain:

```powershell
cargo test -p horizon-mods --lib --locked --offline
cargo check --profile fast -p horizon-client -p horizon-client-lib --bins --locked --offline
cargo build --profile fast -p horizon-client -p horizon-client-lib --bins --locked --offline
```

В этой рабочей копии `CARGO_HOME` указывает на `../.tools/cargo`, `RUSTUP_HOME` — на `../.tools/rustup`, `CARGO_TARGET_DIR` — на `../.tools/native-target`; `bin` Cargo добавляется в PATH. `--offline` использует существующий кэш зависимостей.

Игровые прогоны используют подготовленные ресурсы собственной Minecraft 26.3 и новые отдельные каталоги данных. Ресурсы, сохранения пользователей и старые поставки не входят в изменения исходного кода.
