## Что реализовано

Новый игрок получает читаемую русскую книгу и маркированную грамоту. Применение грамоты к загруженному колоколу деревни расходует предмет и основывает общину. Сервер проверяет дистанцию, две кровати и одного обычного жителя рядом; допускаются поселения игроков. Колокол получает роль ратуши в учёте, постройка не заменяется.

Игрок сначала остаётся гостем. Три самостоятельных представителя общины предлагают проекты каменоломни, припасов и жилья. Передача требует все обычные материалы задания и близость NPC; недостаточный взнос ничего не списывает. Один проект даёт 20 признания, повторный взнос не расходует предметы и не награждается. Три проекта и 60 признания открывают Старосту и городской обзор: 0 дерева, 0 еды, 6 мест жилья.

Основатель приглашает по UUID, гость принимает приглашение. Членство и признание общие; обычный участник не может выдавать приглашения. Состояние сохраняется по миру. Клиенты согласуют протокол отображения самостоятельных NPC; удалённый клиент не получает права менять NPC.

## Компиляция и автоматические проверки

Собраны `horizon-client.exe` и `horizon-ctl.exe`, профиль `fast`, locked dependencies. Форматирование и проверка публичного дерева пройдены. Выполнены 419 автоматических тестов: horizon-mods 36, контроллер NPC 4, сетевой инвентарь 9, loot tables 3, game binary 367. Три игровых теста upstream помечены ignored. Полная parity-матрица и весь workspace не прогонялись.

## Реальные игровые прогоны

Использовался обычный встроенный сервер, отдельные новые миры и подготовленные ресурсы Minecraft 26.3. Хост — видимое окно; второй клиент и независимый NPC-прогон — offscreen с настоящим рендерером.

## Найденные и исправленные ошибки

Сервер терял `minecraft:custom_data` при отправке инвентаря: грамота приходила с именем, но без идентичности. Добавлена передача и тест сетевого round trip. Диагностический ответ больше не выдаёт успешный `error: null`, который CLI считал ошибкой. В тесте книги используется реальная кнопка Done.

Сохранение встроенного сервера ошибочно выбирало dedicated-путь без файла хозяина из-за старого совместимого флага. Теперь используется точная роль сервера. Пустой серверный контекст сохраняет последний снимок игрока; действительное опустошение его инвентаря записывается. Оба состояния проверены перезапуском.

Наблюдавшиеся короткие закрытия первых попыток были командами очистки теста `save`/`quit` после assertion/control-ошибок. В проверенных свежих логах аварийной паники нет. Отдельный прямой запуск `.exe` дал ошибку отсутствующих ресурсов; для поставки предусмотрен и проверяется launcher с автоопределением ресурсов.

## Границы и следующий шаг

Это прототип первого этапа. Разговоры используют чат-консоль; отдельный экран экономики ещё не сделан. Проекты фиксируют восстановление в учёте и пока не строят физические объекты. Нет производственных доходов, управления трудом, технологий, войск, камеры сверху, дипломатии, политики, катаклизмов, загрязнения и космоса. Они разделены на последующие срезы в [дорожной карте](ROADMAP.ru.md).

Корректное сохранение и перезапуск проверены. Файл кампании и данные Minecraft пока не объединены общим журналом аварийных транзакций; этот разрыв нужно устранить перед полноценной экономикой. Выделенный сервер и большие населённые миры отдельно не проверялись. Следующий срез — городской склад, назначение труда, добыча/доставка и физическая стройка.
