# Собранный Horizon из нашего форка — Native NPC API 4

Это отдельное приложение из https://github.com/Den-k-ur/horizon, ветка `codex/civilization-mod-api`. Официальная установка Horizon и оригинальный репозиторий не изменены.

## Запуск

Дважды нажмите **Play-Fork.cmd**. Скрипт найдёт подготовленные ресурсы Minecraft 26.3 в установленном Horizon и запустит **horizon-client.exe из этой папки**. Вручную копировать Minecraft-ассеты не нужно; они не входят в пакет.

Сохранения этого приложения лежат в **game-data**, отдельно от обычных миров. В комплекте есть проверочный мир `OwnedNpcApiProof`: каменная площадка, стена и самостоятельный NPC. Он использует готовую геометрию жителя только как внешний ресурс. Профессия, идентичность и контроллер принадлежат нашему API — ванильные Brain, POI, торговля и распорядок не используются.

Управление персонажем обычное: WASD, мышь, Space; Esc — меню. Тестовая сборка запускается с `--no-pause`, чтобы смена фокуса не останавливала проверку. Точное наличие паузы обычных меню определяется движком. Стратегический интерфейс прежнего `.hmod` пока не перенесён в новый native API.

Если ресурсы не найдены, подготовьте Horizon через официальный лаунчер либо укажите путь:

```powershell
powershell -ExecutionPolicy Bypass -File .\Play-Fork.ps1 -Resources "C:\путь\к\26.3"
```

При проблеме запуска смотрите `game-data/control.log` и `game-data/logs/latest.log`.

## Что уже работает

- Сервер создаёт отдельного NPC; клиент получает и отображает его отдельное зеркало.
- NPC идёт через настоящий A* и физику блоков, обходит препятствие. Перемещение не заменено телепортациями.
- Можно задать цель движения, рабочее действие с длительностью, отменить задачу, сменить профессию и ссылку на внешность.
- Стабильный ключ и владелец не меняются при переназначении. Повторный `ensure` не создаёт дубль.
- Положение, задача и рабочий прогресс сохраняются в `horizon-owned-npcs.json` внутри мира. Выгрузка чанка сохраняет идентичность.
- Удаление убирает отображение и оставляет tombstone для защиты от повторного создания старой выгруженной сущности.

Живой прогон 30.10.2026 подтвердил создание/отображение, обход стены, работу, возврат, отмену/переназначение, перезапуск без дубля и удаление. Подробности — `proof/report.json`, скриншот — `proof/owned-npc.png`.

## API для разработки

Native hooks API4 этого форка: `native_npc_ensure`, `native_npc_state`, `native_npc_set_order`, `native_npc_cancel`, `native_npc_set_profession`, `native_npc_set_appearance`, `native_npc_despawn`. Вызывать из серверного native-hook, а не из окна-клиента. Состояние контролируется встроенным сервером даже в одиночной игре.

Для локального тестирования есть `horizon-ctl owned-npcs JSON`. Пример чтения:

```powershell
.\horizon-ctl.exe --socket .\game-data\control.json owned-npcs '{"owner":"civilization","command":{"operation":"list"}}'
```

В поставленном демо активный ключ — `demo_worker`. Направить его к точке:

```powershell
.\horizon-ctl.exe --socket .\game-data\control.json owned-npcs '{"owner":"civilization","command":{"operation":"set-order","key":"demo_worker","order":{"kind":"move-to","target":{"x":10.5,"y":100,"z":0.5},"arrival_radius":0.6}}}'
```

Количество отображаемых NPC: `horizon-ctl --socket game-data/control.json owned-npc-mirrors`.

## Текущие границы

Это API и проверенный native NPC, а не законченный перенос Civilization. Экономика/город базового `.hmod` сохранены отдельно; соединение стратегического производства с новым NPC-контроллером — следующий этап.

Рабочее действие пока означает таймер и идентификатор действия: оно само не рубит деревья, не строит блоки и не начисляет ресурсы. Для этого нужна логика мода. Сейчас видимость проверена только через собственный integrated server; внешний LAN/дедицированный клиент пока не подключён. NPC не участвует в ванильной торговле, подборе предметов или бою.

Геометрия — подготовленная player/mannequin или villager. Текстуры — существующие ассеты Minecraft в атласе. Импорт пользовательских PNG и новые модели не готовы. Свободной камеры сверху нет.
